# KRILEA — сайт (krilea.eu)

Този проект е изграден с [Astro](https://astro.build) (статичен сайт, максимална скорост) и [Decap CMS](https://decapcms.org) за самостоятелно публикуване на статии през `/admin`, хостван в [Netlify](https://netlify.com).

Настоящият документ е написан за човек без технически опит и описва всичко нужно, за да качите сайта онлайн и да го управлявате занапред.

## 1. Локално разглеждане на сайта

Нужен е инсталиран [Node.js](https://nodejs.org) (версия 22 или по-нова — на тази машина вече е инсталиран).

```bash
npm install
npm run dev
```

Сайтът ще се отвори на адрес `http://localhost:4321`. Спиране: `Ctrl + C` в терминала.

За да видите как ще изглежда точно финалният, публикуван сайт (по-близко до реалността от `npm run dev`):

```bash
npm run build
npm run preview
```

## 2. Качване в GitHub

1. Създайте безплатен акаунт в [github.com](https://github.com), ако все още нямате.
2. Създайте ново, **празно** хранилище (repository) — например с име `krilea-website`. Не добавяйте README, `.gitignore` или лиценз при създаването — те вече съществуват в проекта.
3. В терминала, в папката на проекта, изпълнете (заменете адреса с вашия):

```bash
git add .
git commit -m "Начална версия на сайта KRILEA"
git remote add origin https://github.com/ВАШЕТО-ПОТРЕБИТЕЛСКО-ИМЕ/krilea-website.git
git push -u origin main
```

Ще ви бъде поискан вход в GitHub (потребителско име и токен за достъп, не паролата ви — GitHub ще ви упъти).

## 3. Свързване с Netlify

1. Регистрирайте се безплатно в [netlify.com](https://netlify.com), най-лесно през бутона „Sign up with GitHub“.
2. От таблото изберете **Add new site → Import an existing project → Deploy with GitHub**.
3. Изберете хранилището `krilea-website`.
4. Netlify автоматично разпознава настройките от файла `netlify.toml` в проекта:
   - Build command: `npm run build`
   - Publish directory: `dist`
5. Натиснете **Deploy**. След 1–2 минути сайтът ще бъде достъпен на временен адрес от вида `random-name-123.netlify.app`.

Всяко следващо качване (push) към клона `main` в GitHub автоматично ще пусне нова публикация на сайта.

## 4. Вход в системата за управление на съдържание (/admin)

Сайтът използва **Netlify Identity** за защита на входа в `/admin`.

1. В Netlify отворете сайта си → **Site configuration → Identity → Enable Identity**.
2. В **Identity → Registration** изберете **Invite only** (за да не може произволен човек да се регистрира).
3. В **Identity → Services** включете **Git Gateway** (бутон „Enable Git Gateway“) — това позволява на Decap CMS да записва статии директно в GitHub хранилището от ваше име.
4. В **Identity → Invite users** въведете своя имейл адрес и изпратете покана.
5. Ще получите имейл — отворете връзката в него, тя ще ви отведе към `/admin` на сайта, където ще зададете парола.
6. Оттам нататък влизате на `https://krilea.eu/admin/` с имейл и парола.

## 5. Свързване на домейна krilea.eu (GoDaddy)

Домейнът остава закупен в GoDaddy — само сочим неговия DNS към Netlify.

1. В Netlify: **Site configuration → Domain management → Add a domain** → въведете `krilea.eu`.
2. Netlify ще ви покаже нужните DNS записи. Обичайно те са:

   | Тип   | Име (host) | Стойност                    |
   | ----- | ---------- | ---------------------------- |
   | A     | `@`        | `75.2.60.5`                   |
   | CNAME | `www`      | `random-name-123.netlify.app` |

   (Точната IP адрес/стойност винаги проверявайте в Netlify — може да е различна към момента на настройка.)

3. Влезте в акаунта си в **GoDaddy → My Products → DNS** до домейна `krilea.eu`.
4. Добавете/редактирайте записите A и CNAME с горните стойности (изтрийте евентуален съществуващ „parking“ A запис на GoDaddy).
5. DNS промените отнемат от няколко минути до няколко часа, за да се разпространят.
6. Обратно в Netlify, изчакайте статусът на домейна да стане „Netlify DNS“ / зелена отметка и включете **HTTPS** (Netlify издава безплатен SSL сертификат автоматично след потвърждение на домейна).

## 6. Бюлетин — свързване с MailerLite

Формата за абонамент изпраща имейлите през малка защитена функция (Netlify Function), не директно от браузъра — затова API ключът никога не се показва публично.

1. Регистрирайте се в [mailerlite.com](https://www.mailerlite.com) (има безплатен план).
2. Създайте група за абонати, например „KRILEA — сайт“: **Subscribers → Groups → Create group**.
3. Отворете групата — в адреса на браузъра ще видите нейното ID (число), например `.../groups/123456789012345678`. Копирайте числото.
4. За API ключ: **Integrations → API** (в по-новия интерфейс: профилна снимка горе вдясно → **Integrations → Developer API**) → **Generate new token**. Копирайте токена — показва се само веднъж.
5. В Netlify: **Site configuration → Environment variables → Add a variable**, добавете:
   - `MAILERLITE_API_KEY` = токенът от стъпка 4
   - `MAILERLITE_GROUP_ID` = числото от стъпка 3
6. Направете нов деплой (**Deploys → Trigger deploy → Deploy site**), за да влязат в сила новите променливи.

След това формата за абонамент на сайта ще добавя новите имейли директно в тази група в MailerLite.

## 7. Как да публикувате статия

1. Отидете на `https://krilea.eu/admin/` и влезте с вашия имейл и парола.
2. От менюто вляво изберете **„Статии (Журнал)“**.
3. Натиснете **„New Статия“** (Нова статия).
4. Попълнете полетата:
   - **Заглавие**
   - **Кратко описание** — показва се в картите и при споделяне в социални мрежи
   - **Дата на публикуване**
   - **Корица** — плъзнете и пуснете изображение (препоръчително около 1600×960 пиксела, под 500 KB)
   - **Алтернативен текст на корицата** — кратко описание на снимката (важно за достъпност и SEO)
   - **Тагове** — по избор
   - **Чернова** — докато е включено, статията НЕ се показва на живия сайт; изключете я, когато сте готови да публикувате
   - **Съдържание** — самият текст, с визуален редактор (удебелен текст, заглавия, цитати, снимки, връзки)
5. Натиснете **„Publish“** (Публикувай) горе вдясно.
6. След около 1 минута (времето за нов деплой в Netlify) статията се появява на живия сайт в `/zhurnal/`.

Двете примерни статии в момента са с истинско, но временно съдържание — редактирайте ги директно през `/admin`, за да ги замените с окончателните текстове.

## 8. Смяна на връзки към социални мрежи

Отворете файла [`src/config/site.ts`](src/config/site.ts) и редактирайте обекта `SOCIAL`:

```ts
export const SOCIAL = {
  instagram: 'https://www.instagram.com/вашия-профил',
  facebook: 'https://www.facebook.com/вашата-страница',
  tiktok: '',     // оставете празно, за да остане скрито
  pinterest: '',
  youtube: '',
};
```

Запазете файла, качете промяната в GitHub (`git add`, `git commit`, `git push`) — Netlify ще публикува новата версия автоматично.

## 9. Активиране на статистика за посещенията

Сайтът е подготвен за **Cloudflare Web Analytics** — безплатен инструмент, който не използва проследяващи бисквитки.

1. Регистрирайте се безплатно в [Cloudflare](https://www.cloudflare.com) → **Analytics & Logs → Web Analytics → Add a site**.
2. Въведете `krilea.eu`. Cloudflare ще генерира малък код с поле `data-cf-beacon='{"token": "..."}'` — копирайте само стойността на `token`.
3. В Netlify: **Site configuration → Environment variables**, добавете:
   - `PUBLIC_CF_BEACON_TOKEN` = копираният token
4. Направете нов деплой. Статистиката ще започне да се появява в таблото на Cloudflare до няколко минути.

Ако предпочитате [Plausible](https://plausible.io) вместо Cloudflare, кажете и ще добавим съответния скрипт по същия начин.

## 11. Смяна на пеперудата с по-качествено изображение

Илюстрацията на пеперудата в момента е изрязана от предоставения мудборд (`КРИЛЕЯ.png`) и е с ограничена резолюция. Когато имате готов чист файл (за предпочитане PNG с прозрачен фон, поне 1000×1000 пиксела, или SVG):

1. Заменете файла [`src/assets/logo/butterfly.png`](src/assets/logo/butterfly.png) с новото изображение (запазете същото име, или обновете импортите в `Header.astro`, `Hero.astro`, `za-branda.astro` и `404.astro`, ако смените името).
2. По желание — прегенерирайте OG изображението и favicon-a с новата версия (скриптовете в папка [`scripts/`](scripts) показват как е направено първоначално; изискват временно `npm install --no-save @resvg/resvg-js wawoff2`).

## 12. Фаза 2 — отзиви и бъдещ магазин

Архитектурата е подготвена, но нищо от това не е видимо на сайта, докато не го активирате изрично.

**Секция „Отзиви“:**
- Колекцията вече съществува в [`src/content.config.ts`](src/content.config.ts) (полета: име, текст, оценка, дата, публикуван).
- За да я включите: добавете колекция в `public/admin/config.yml` (примерът за „reviews“ вече е там), създайте компонент `ReviewCard.astro` по образец на `ArticleCard.astro`, и добавете секция в желаната страница, която чете `getCollection('reviews', ({data}) => data.published)`.

**Бъдещ магазин:**
- Добавете нова страница `src/pages/produkti/index.astro` и нова навигационна връзка в `src/config/site.ts` → `NAV`.
- Ако продуктите се нуждаят от собствена колекция съдържание, създайте я по образец на `blog` в `src/content.config.ts`.

## 13. Файлова структура накратко

```
src/
├── components/       Преизползваеми части (хедър, футър, форми, икони)
├── config/site.ts     Централни настройки — навигация, контакти, социални мрежи
├── content/blog/       Статиите (Markdown файлове, управлявани от /admin)
├── content/reviews/    Фаза 2 — отзиви (неактивно)
├── layouts/            Общи шаблони на страниците
├── pages/               Всяка страница на сайта
└── styles/global.css   Цветове, шрифтове, основни стилове

public/
├── admin/               Decap CMS (config.yml + index.html)
├── uploads/blog/        Качените от /admin корици на статии
└── favicon*, og-default.png   Икони и изображение за споделяне

netlify/functions/subscribe.js   Изпращане на нови абонати към MailerLite
scripts/                          Еднократни скриптове за генериране на лого/favicon/OG активи
```
